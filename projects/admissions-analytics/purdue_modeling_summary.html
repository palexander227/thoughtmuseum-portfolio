Purdue Admissions Analytics

A first-pass synthetic modeling prototype for structured application analysis
This prototype transforms Purdue application PDFs into a structured feature matrix, then uses synthetic admissions labels to test the full modeling pipeline before true admissions outcomes are available.

1. From PDFs to a Feature Matrix

The first milestone was converting raw application PDFs into a row-by-row applicant dataset. Each applicant becomes a vector of extracted features:

\[ x_i = (\text{GPA}_i,\ \text{SAT}_i,\ \text{APCount}_i,\ \text{DualEnrollment}_i,\ \ldots) \]

In the current Purdue prototype, the parser produced a table of 222 applicants with fields including GPA, SAT/ACT information, AP count, dual-enrollment count, honors-course count, honors text, activities text, and writing text.

2. Why Synthetic Labels?

At this stage, true Purdue admissions outcomes are not yet available. Rather than wait, we created synthetic admissions outcomes in order to test the analytics infrastructure. These labels are not interpreted as real admissions decisions. They are used as a controlled experiment.

The purpose is to ask:

  • Can the parser produce stable numeric features?
  • Can missing values be handled sensibly?
  • Can a model recover a known latent structure?
  • Can the pipeline produce interpretable rankings and diagnostics?

3. Latent Strength Model

We constructed a synthetic latent strength score from several applicant features:

\[ S_i = 2.0\,\text{GPA}_i + 0.0025\,\text{SAT}_i + 0.18\,\text{APCount}_i + 0.15\,\text{DualEnrollment}_i + 0.10\,\text{HonorsCourseCount}_i + \varepsilon_i \]

The noise term \( \varepsilon_i \) represents unobserved factors: essays, recommendations, institutional priorities, committee variability, and other sources of uncertainty.

4. From Strength to Probability

The latent score was converted into an admissions probability using the logistic function:

\[ p_i = \frac{1}{1 + e^{-(S_i - 12)}} \]

This creates soft probabilistic boundaries rather than a deterministic cutoff. Strong applicants can still be rejected, and weaker applicants can occasionally be admitted.

5. Synthetic Admissions Outcomes

For each applicant, we then sampled a synthetic admissions outcome:

\[ Y_i \sim \operatorname{Bernoulli}(p_i) \]

This gives a simulated admit/reject class that can be used to test logistic regression, ROC/AUC analysis, feature scaling, missing-data handling, and downstream visualizations.

6. Logistic Regression as an Inverse Test

After generating synthetic outcomes, we trained a logistic regression model to see whether the model could recover the structure we intentionally placed into the data.

\[ \Pr(Y_i = 1 \mid x_i) = \frac{1}{1 + e^{-(\beta_0 + \beta^\top x_i)}} \]

This is not yet a claim about Purdue admissions. It is a pipeline validation test: if the model cannot recover a known synthetic signal, the feature extraction or modeling pipeline needs attention.

7. Interpretation

The resulting predicted probability column should be understood as a reconstructed synthetic strength estimate, not a real Purdue admissions probability.

The value of the experiment is methodological: it shows that the project has moved from document parsing into experimental admissions analytics.

Talking points for discussion:
  • We now have a working PDF-to-feature pipeline for Purdue applications.
  • Synthetic labels allow us to test the analytics system before true outcomes arrive.
  • The model is currently validating infrastructure, not making real admissions claims.
  • Once actual outcomes are available, the same pipeline can be recalibrated and tested.
  • The next step is richer feature engineering: research quality, awards taxonomy, course rigor, and essay structure.

8. Next Steps

  • Replace synthetic labels with true Purdue outcomes when available.
  • Compare synthetic predictions against actual admitted/rejected classes.
  • Transfer models trained on CMU data to Purdue as applicant-strength estimators.
  • Pool CMU, UC, and Purdue datasets to test institutional homogeneity and feature transferability.
  • Engineer richer features from activities, honors, essays, and course trajectories.
